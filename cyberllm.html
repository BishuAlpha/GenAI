CyberLLM: Multi-Model Cybersecurity Language Models

A family of small language models trained from random initialization. A router reads the input, picks the matching domain specialist, and falls back to a general model when it is not confident. Everything on this page is interactive and mirrors the implemented code and PLAN.md.

Open-source release and vLLM

The models are built to be published and served with standard tools. Two decisions make that possible, and a third is an honest caveat.

Safetensors

Exported weights are safetensors, a plain tensor format that cannot run code on load. Training checkpoints (.pt, pickle) stay internal and are never shared.

Implemented and tested

Llama architecture

RMSNorm, rotary embeddings, SwiGLU and no biases is exactly Llama. Export renames tensors and splits the fused QKV matrix, so no custom code or trust_remote_code is needed.

Logits match transformers in tests

vLLM: untested here

vLLM lists LlamaForCausalLM, so the export should serve with vllm serve. It has not been run in this repository because the development machine has no GPU and no vLLM.

Choosing how to serve

vLLM serves one model per process and exposes OpenAI-style endpoints. For these base models use /v1/completions; /v1/chat/completions needs a chat template that the models do not have. The router is a classifier, so vLLM cannot serve it: it runs in PyTorch in front of the vLLM servers.

EndpointUse for CyberLLM
POST /v1/completionsYes. Plain text completion, which is what a base model does
POST /v1/chat/completionsOnly with a chat template (--chat-template); otherwise requests error
GET /v1/modelsList the served model
GET /healthLiveness check
pip install vllm
vllm serve artifacts/export/general --max-model-len 512

curl http://localhost:8000/v1/completions -H "Content-Type: application/json" \
  -d '{"model": "artifacts/export/general", "prompt": "A heap overflow in the parser allows", "max_tokens": 64}'

Context is 512 tokens, so keep prompt plus completion within it. Flags and defaults belong to your installed vLLM version: check vllm serve --help and pin versions.

Publishing as open source

The code is Apache-2.0. For weights, choose a licence deliberately and make sure it is compatible with every data licence: weights are derived from the training data, so a source that forbids redistributing derived works can block release. This is a legal decision, not a technical one.

  • Publish each specialist as its own repository, for example cyberllm-vulnerability, and link them from the general model's card. Keep tokens in the CLI login, never in the repository.
  • Verify after every export and every vLLM or transformers upgrade: sha256sum -c SHA256SUMS, pytest tests/test_export.py, and a greedy-decoding comparison between the server and transformers.
  • Security: share safetensors, never .pt; do not enable trust_remote_code; put the server behind authentication; treat model output as untrusted text.

The full guide, with the tensor mapping, vLLM caveats, troubleshooting and release checklist, is in DEPLOYMENT.md.

Vision and multi-model design

Why multiple models

At around 9M parameters a single model has very little capacity to share across CVE text, malware write-ups and incident playbooks. Splitting by domain concentrates capacity, lets each corpus be tuned independently, and isolates the damage from a bad data source. The cost is routing errors, which the confidence threshold and general fallback are designed to contain.

ConcernSingle modelRouter + specialists
Capacity at ~9M parametersShared across all domains, dilutedConcentrated per domain
Data mixtureOne global mixture to tunePer-domain corpora, iterate independently
Failure isolationA bad source degrades everythingOnly one specialist is affected
Inference computeWhole model each timeSmall router plus one specialist
Adding a domainRetrain everythingTrain one model and one router label
Main riskDilutionMis-routing of cross-domain questions (experiment E9, E10)

Domains

Training uses defensive, structured text only. Malware binaries and raw executable samples are out of scope. Public availability is not a licence: every source must be checked for reuse and redistribution terms.

System architecture

Routing flow

The router is a 4-layer Transformer classifier with mean pooling. If its top probability is below the confidence threshold, or the chosen specialist has no checkpoint, the general model answers. Specialists load lazily, so only models in use occupy memory.

Threshold trade-off

A higher threshold sends fewer requests to specialists (lower coverage) but those that pass are more likely correct. Experiment E10 measures this on held-out data. The curves below are a synthetic illustration of the shape of the trade-off, not measured results.

Model architecture

Parameter budget

Decoder-only Transformer: RMSNorm (pre-norm), RoPE, SwiGLU, causal attention through scaled_dot_product_attention, tied embeddings. The default configuration has exactly 8,917,248 trainable parameters, asserted in tests/test_model.py.

Correction to the v1.0 plan. It paired a 384 hidden size with a ~10M target. With an 8,192 vocabulary, 384 hidden is 17.3M parameters. The 256 / 4 heads / 768 setting is what produces 8.92M, so it is the default.

Inside one Transformer block

Each of the 8 blocks applies attention then a feed-forward network, both with residual connections and pre-normalization. Step through it to see tensor shapes.

Rotary position embeddings

RoPE rotates each pair of query and key features by an angle proportional to token position. The attention score then depends only on the distance between tokens, not their absolute positions. Low-index pairs rotate fast (local detail); high-index pairs rotate slowly (long range).

Causal attention

Every position may attend only to itself and earlier positions. The test test_attention_is_causal changes the last token and checks that all earlier outputs are unchanged.

Data pipeline

Pipeline stages

Cleaning, deduplication and splits

Cleaning applies NFKC normalization, strips control characters, trims trailing whitespace and collapses blank lines. Exact duplicates are dropped across the whole corpus by SHA-256. The split is derived from the content hash, so a document never moves between train and validation when the pipeline is rerun.

Provenance manifest

Every kept document has a manifest record so any training example can be traced to its origin and licence review.

Training and compute

Learning-rate schedule

AdamW with linear warmup followed by cosine decay to a floor. Weight decay applies to weight matrices only, never to norms or biases. Gradients are clipped to norm 1.0.

Compute budget

  • Precision: auto uses bf16 on CUDA devices that support it, otherwise fp32. fp16 uses a gradient scaler.
  • Checkpointing: writes are atomic (temp file then rename). latest.pt carries optimizer state for --resume; best.pt tracks lowest validation loss.
  • Smoke test: configs/smoke.yaml runs the whole pipeline with a tiny model on a CPU.

Quality gates

  • Ruff lint and format checks pass; Python 3.11 or newer, typed throughout.
  • 36 tests cover shapes, gradient finiteness, causality, RoPE norm preservation, padding invariance in the classifier, config validation, data cleaning, corpus audit, safetensors export checked against transformers, and an end-to-end run: prepare, tokenize, encode, train, resume, evaluate, route, generate.
  • Dependencies are minimal: PyTorch, NumPy, safetensors, tokenizers (tokenizer only, no pretrained vocabulary), PyYAML. transformers is a dev dependency used only to verify the export.

Training data guide

The full reference is DATA.md. This section is the interactive version: what data goes in, how it must be formatted, how much you need, how to check balance, and how to tell from the loss curves whether training went well. The checks here use the same thresholds as the cyberllm audit command.

Data types by domain

The folder a file sits in is its label, and the router learns from it. Put each document where it belongs. Training text is defensive prose and structured records: descriptions, advisories, reports, playbooks and guidance. It is never malware binaries, raw executables, working exploit chains, credentials or personal data.

Raw data format

Place .txt, .md or .jsonl files under data/raw/<domain>/. A plain file is one document. In JSONL, each line is one document with a required text field and optional id, source and source_url. Set source: the audit uses it to detect a domain that is really one vendor's writing.

FieldRequiredDefault when missing
textyesLine is invalid and prepare stops
idno<file>:<line>
sourcenoThe file path
source_urlnoEmpty

Try the validator. It applies the same cleaning, length filter and exact deduplication as prepare. Edit the lines, or change min_chars.

Structured feeds are not training text as they are. NVD JSON and ATT&CK STIX should be flattened into readable prose with a consistent template per source. Fetchers for these feeds are planned (milestone M2); until then you convert them yourself.

Quantity: how much is enough

A run consumes batch x accumulation x context x max_steps tokens. The default is 327.68M, about 37 tokens per parameter. The audit warns when the planned run is more than 4 passes over a domain's data, because gains flatten and memorization rises.

UseRough minimumWhy
Pipeline smoke testA few hundred documentsChecks the plumbing only
Router50+ documents per domain, 200+ betterNeeds enough windows per class
A specialist better than noiseTens of millions of tokensBelow that, loss mostly memorizes
Meaningful perplexity comparison10,240+ validation tokens per domain20 context windows for a stable estimate

Public structured feeds are smaller than the default budget. NVD is tens of millions of very repetitive tokens; CWE and ATT&CK are each a few million at most. One such source will not fill 328M tokens, and repeating it mostly teaches the template. Lower max_steps, add prose-heavy sources (advisories, reports, guides, playbooks), and rely on the general model for domains too small for their own specialist. Run cyberllm audit before deciding.

Balance across domains

An unbalanced corpus skews the general model toward the biggest domain and teaches the router to predict the common class. The audit warns when the largest domain is more than 5x the smallest, or when one source supplies more than 80% of a domain. Move the sliders, then try the two fixes.

  1. Collect more of the small domain. Best fix; nothing is thrown away.
  2. Cap the big domain for the general model by sampling fewer of its documents before prepare.
  3. Upsample the small domain. Cheap, but repeats raise memorization; stay inside the 4-epoch limit.
  4. Accept it for specialists. A specialist trains only on its own domain, so imbalance matters mainly for the general model and the router.

Training and reading the curves

Train general first (it is the fallback and your baseline), then specialists one at a time, then the router. A specialist that is not better than the general model on its own domain (experiment E9) is not earning its place.

cyberllm prepare
cyberllm audit              # fix warnings before continuing
cyberllm tokenizer
cyberllm encode
cyberllm audit              # token-level checks

cyberllm train --domain general
cyberllm train --domain vulnerability
cyberllm train-router
cyberllm evaluate --domain general

Pick a pattern to see what it looks like and what to change.

Changing the tokenizer changes token ids and invalidates every checkpoint, so retrain after any tokenizer change. Changing only the data means re-running prepare, tokenizer and encode.

Evaluation data

  • Today: validation loss and perplexity per domain (cyberllm evaluate), and router validation accuracy each epoch. Perplexity only compares models that share a tokenizer and validation set.
  • Planned: held-out CWE, ATT&CK and malware-report classification, and security question answering, on independent labelled datasets.
  • Rules: no overlap with training, including near-duplicates; prefer a time-based holdout for vulnerabilities and threats; keep a validation set for decisions and a separate test set for the final number; report more than perplexity; check for memorization before claiming results.

Licensing, privacy and safety

  • Public availability is not a licence. Record the licence of every source; the manifest keeps source_url and retrieval_date.
  • Share manifest.jsonl (no text) rather than corpus.jsonl unless licences allow redistribution. data/, outputs/ and artifacts/ are git-ignored.
  • Redact usernames, emails, hostnames, tokens and keys from incident material. A model can reproduce what it saw.
  • Generated output is not authoritative. A small model hallucinates identifiers, scores and fixes; verify independently.

Known limitations

  1. No real corpus is bundled yet; the pipeline is verified on synthetic data only.
  2. Splits are hash-based, not yet source-aware or time-aware.
  3. Only exact deduplication; near-duplicate detection (MinHash) is planned.
  4. No document-boundary attention masking or sequence packing.
  5. Single-process training; no distributed training yet.
  6. No experiment tracking or multi-seed statistics yet.
  7. Router robustness on mixed-domain and adversarial inputs is untested.
